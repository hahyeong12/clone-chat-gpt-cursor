## 2. 검증 과정에서 확인한 문제

### 응답에서 공백이 사라짐 — 실제 확인

`lib/medication-ai.ts`에서 응답을 **문자 하나씩** SSE로 보냅니다. `lib/stream.ts`가 이벤트 단위를 읽을 때 텍스트 전체에 `.trim()`을 적용하므로 **공백 문자만으로 구성된 데이터 이벤트가 사라집니다.**

따라서 내용이 오가더라도 문장 사이의 공백·줄바꿈이 훼손될 수 있습니다. 브라우저 검사에서 실제로 공백 손실을 확인했습니다.

**다시 만들 경우:** SSE 라인 구분을 하되 `data:` 뒤의 유효한 공백 데이터는 보존하는 파서를 작성하고, 문장·빈칸·줄바꿈이 포함된 응답으로 테스트해야 합니다.

### 사용자별 개인화 — 코드 구조상 정상 동작을 보장하지 못함

`lib/user-profile.ts`의 사용자 프로필은 모듈 내부 `Map`에 저장됩니다. `initializeTestUsers()`는 클라이언트 화면과 로그인 컴포넌트에서 호출되며, 서버의 `app/api/chat/route.ts`는 `userId`로 서버 측 `getUserProfile()`을 조회합니다.

클라이언트와 서버의 모듈 메모리는 공유되지 않으므로, 화면의 로그인 상태와 서버의 개인화 프로필 조회는 연결되지 않습니다. **브라우저에서 로그인 이름이 나온 것만으로 개인화 추천이 실제 적용됐다고 할 수 없습니다.** 이 항목은 서버 프로필 조회 구조를 토대로 한 검토이며, 계정별 응답 차이를 자동 테스트한 결과는 아닙니다.

### 데이터의 신뢰성 — 별도 검증 필요

의약품 자료는 `lib/medications.ts`에 하드코딩되어 있습니다. 일부 항목에 부정확한 제품·성분·용법이 포함되어 있을 수 있고, 공식 의료 정보 출처와 검증 이력이 없습니다. **실제 복용·처방 판단에 사용해서는 안 됩니다.**

### 의존성 보안 경고 — 재검토 필요

2026-11-15 GitHub Actions의 `npm ci` 출력에서 **의존성 취약점 경고 12건(낮음 3, 높음 7, 심각 2)**이 확인되었습니다. 이는 패키지 감사 결과이며, 곧바로 해당 사이트에 실질적으로 악용 가능한 취약점이 12개 있다고 단정하는 의미는 아닙니다. 현재의 설치 패키지와 사용 범위를 대상으로 별도 보안 검토가 필요합니다.

**이 아카이브를 일반인 대상 의료 서비스로 공개 배포하지 않는 이유** 중 하나입니다.

## 4. 실행 방법

Node.js 22 기준:

```bash
npm ci
npm run build
npm run start
```

브라우저에서 `http://localhost:3000/home` 또는 `http://localhost:3000/`을 엽니다.

개발 모드에서는 `npm run dev`를 사용할 수 있습니다.

**의료 판단용 사용 금지.** 서비스가 로컬에서 실행되는 것과 안전한 의료 소프트웨어라는 것은 전혀 다른 문제입니다.
