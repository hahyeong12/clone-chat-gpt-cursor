# 약장수 기술 검토 노트

> **검토 기준:** GitHub에 남아 있는 2025년 애플리케이션 코드. 2026년의 관점에서 재검토한 문서입니다. 2026년 11월에 프로덕션 서버·실제 브라우저 재현 검증을 추가했습니다. **의료 정보의 개별 항목을 의학적으로 검증한 결과는 아닙니다.** [실행·검증 기록](verification-2026.md)을 참조하세요.

## 실제 구조

```text
app/home/page.tsx       의약품 검색·카테고리 필터 UI
  └─ lib/medications.ts 정적 의약품 20개

app/page.tsx            로그인·채팅 UI
  ├─ components/login-dialog.tsx
  ├─ lib/user-profile.ts (테스트 프로필, 데모 인증)
  └─ lib/stream.ts      HTTP 요청과 SSE 수신
       └─ app/api/chat/route.ts
            ├─ lib/medication-ai.ts (규칙 기반 증상 분석·추천)
            └─ lib/user-profile.ts (서버 측 프로필 조회)
```

## 기능별 확인과 한계

### 1. 챗봇이 곧 LLM은 아니다

`lib/medication-ai.ts`는 증상 키워드·정규식·조건문을 바탕으로 답변을 조립하고, 문자에 짧은 지연을 주어 스트리밍합니다. `app/api/chat/route.ts`는 이 함수를 호출합니다.

`lib/ai.ts`에는 OpenAI API 스트리밍 코드가 있지만 **현재 이 채팅 경로에 연결되어 있지 않습니다.** `OPENAI_API_KEY`를 설정한다고 곧바로 약장수 답변이 LLM 기반으로 바뀌는 구조는 아닙니다.

### 2. 프로필 정보가 서버로 실제 전달되는가?

클라이언트의 `app/page.tsx` 및 `components/login-dialog.tsx`는 테스트 계정을 초기화하고, `userId`만 API로 전달합니다. 서버는 `getUserProfile(userId)`로 다시 조회합니다.

그러나 `lib/user-profile.ts`의 저장소는 프로세스 메모리의 `Map`이고, 브라우저에서 초기화한 데이터가 **서버 측 모듈 메모리에 자동으로 공유되지 않습니다.** 브라우저에서는 데모 로그인 표시가 동작함을 확인했지만, 서버 측 사용자 정보 저장소가 별개이므로 이 사실만으로 개인화 추천 기능이 제대로 작동한다고 말할 수 없습니다. **서버의 계정별 응답 차이는 이번 테스트에서 검증하지 않았습니다.**

### 3. 테스트 로그인은 실제 인증이 아니다

`lib/user-profile.ts`의 데모 비밀번호는 코드에 고정되어 있고, 로그인 검증을 클라이언트에서 수행합니다. 이는 테스트 인터페이스이며 실제 사용자 인증·권한 관리로 간주하면 안 됩니다.

### 4. 의료 데이터의 신뢰성을 보장할 수 없다

`lib/medications.ts`는 의약품의 제품명, 성분, 적용 증상, 용법 등을 코드에 직접 기입합니다. 일부 제품명·성분·분류가 실제 의약품 정보와 일치하지 않는 것으로 보이는 항목이 있으며, 공식 출처나 검증 프로세스가 없습니다. **이 목록은 실제 의약품 데이터베이스나 복용 안내로 사용해서는 안 됩니다.**

정확하지 않은 데이터에 자동 추천 로직을 연결한 것이 이 프로젝트의 가장 중요한 한계입니다. 알레르기·기저질환 조건이 일부 구현돼 있어도 의료적 적합성 또는 안전성을 입증하지 못합니다.

### 5. 테스트와 API 방어

2025년 당시 `package.json`에는 자동 테스트 스크립트가 없었습니다. **2026년 11월에** GitHub Actions와 `scripts/smoke-test.mjs`, `scripts/browser-smoke.mjs`를 추가해 프로덕션 서버·HTTP·브라우저 기본 흐름을 확인했습니다. 메시지 배열 검증과 에러 응답 코드는 있지만, 입력 스키마·서버 측 사용자 검증·의료 정보 안전성 테스트는 보완해야 합니다.

### 6. 공백이 사라지는 SSE 응답 처리

서버는 글자 하나씩 SSE 데이터로 보내고, `lib/stream.ts`는 이벤트 텍스트에 `.trim()`을 적용해 해석합니다. **공백만 담은 이벤트가 사라져 채팅 응답의 띄어쓰기가 손실되는 문제를 실제 Chromium 검사에서 확인했습니다.** 2025년 코드 상태를 남기기 위해 이번 문서 작업에서는 고치지 않았습니다.

### 7. 의존성 보안 경고

2026년 11월 `npm ci` 설치 로그에는 12건의 패키지 취약점 경고(낮음 3, 높음 7, 심각 2)가 나타났습니다. 모든 항목이 실제 서비스에서 악용 가능함을 의미하는 것은 아니지만, 현재 의존성 그대로 운영하려면 별도 보안 검토와 업데이트가 필요합니다.

## 다시 개발한다면

1. **문제 재정의:** '약을 추천한다'보다 출처가 명확한 **공개 의약품 정보 검색·설명**으로 범위를 제한합니다.
2. **데이터 검증:** 신뢰할 수 있는 공공기관·제품 허가 정보와 출처/갱신일을 저장합니다. 복용량을 추론해 생성하지 않습니다.
3. **구조 정리:** 클라이언트/서버 데이터 흐름을 나누고, 테스트 계정과 진짜 인증을 혼동하지 않도록 합니다.
4. **검증 강화:** 검색, 필터, API 응답, 오류 처리, 안전 안내를 자동 테스트합니다.
5. **AI 기능 분리:** 실제 LLM 호출 여부와 규칙 기반 처리 여부를 UI·문서에 명시합니다.

단, **이 저장소에서는 옛 코드를 통째로 새 제품처럼 개조하지 않습니다.** 위 항목은 학습·성장 관점의 개선 제안입니다. 실제 새로운 서비스를 만든다면 별도 프로젝트로 진행하는 편이 당시 개발 기록을 보존하기에 좋습니다.
